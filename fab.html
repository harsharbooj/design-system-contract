Icon Button "Fab buttons" sheet · 8 instances (4 Variant × 2 Size) · node 768:5503

A square, icon-only action button — the component every other section pointed to for icon-only actions (Button's leading/trailing icons, the Tag close icon, table row actions) but that had never been documented on its own. Rendered here with the same Edit glyph the source file uses throughout the sheet; swap the instance-swapped icon per use, everything else about the container stays fixed.

The sheet's own column headers don't match the component's variant property. Figma labels the four columns Default / Hover / Error / Disabled — reading like a live interaction-state matrix — but the underlying instances are actually four different Variant values (Primary, Secondary, Destructive, Disabled). There is no real :hover or :focus state defined anywhere on this component; "Hover" here just means "the Secondary color variant, shown as an example of what a hover treatment could look like." Code should not wire a CSS :hover selector expecting it to swap in the Secondary token — it has to be done deliberately in the component layer.

Anatomy

      

        

        
    
          
  1. Container — a fixed square, 38×38 (Medium) or 30×30 (Small), radius/xs (4). Fill and border key off Variant, not off any interaction state.
    2. 
          
  2. Fill + border — Primary and Destructive share bg/canvas fill + border/strong stroke; Secondary swaps the fill to bg/sunken, same border; Disabled also fills bg/sunken but drops the border entirely.
    3. 
          
  3. Icon — instance-swap slot, centered, size/icon-md (20, Medium) or size/icon-sm (16, Small). Color is the one thing that actually changes per Variant: icon/primary for Primary/Secondary, icon/destructive for Destructive, a muted disabled tone for Disabled.
    4. 
          
  4. No label slot. Unlike Button, there is no text — the entire affordance is the icon, which is exactly why every instance needs an external aria-label (see Accessibility).

Accessibility

      

        
Render a native <button> with a mandatory aria-label describing the action ("Edit row", "Delete project") — the icon alone conveys nothing to assistive tech. This is the one rule every other section already deferred to this component for.

        
Pair with a visible tooltip on hover/focus for sighted mouse users, since there is no text label in the layout to fall back on.

        
Disabled uses :disabled / aria-disabled="true" and removes the border — never rely on the muted icon color alone to signal non-interactivity.

        
Focus is keyboard-visible via focus/ring. Gap: no Focus variant exists in Figma (same gap already flagged on Button and Input) — wire :focus-visible in code until one is added.

      


      
Usage rules

      

        
Use Primary for the default/standalone icon action in a toolbar or row. Reach for Destructive only when the action is irreversible (delete, remove) — same rule Button already sets for its own Danger type.

        
Don't read Secondary as an actual :hover state to wire in CSS — it's a distinct Variant an agent chooses at author time (e.g. a "currently selected" row's action), not something the browser toggles automatically.

        
Default to Medium (38) in toolbars and page headers; drop to Small (30) only inside dense table rows, matching Button's own Medium/Small guidance.

        
Compose from this component and swap only the inner icon — never rebuild the square from a styled div, and never hardcode border-strong's hex.

Findings from this pass
no Figma edits made — surface for review before a consistency pass

      

        
Found
Column headers imply states that don't exist. Default / Hover / Error / Disabled read as a live interaction-state matrix, but the actual property is Variant = Primary / Secondary / Destructive / Disabled. Recommend renaming the sheet's column headers to the real variant names, or — better — adding true Hover/Focus state variants so the labels stop overpromising.

        
Found
No real Size axis. The 38px and 30px rows are two separately-authored components that each report Size=MD in their own variant name. Consolidate into one component set with a genuine Size = MD | SM property, the way Button already does.

        
Found
38×38 and 30×30 have no size/* token. Both are off the size/control-* scale (28/36/44) — same category of gap as the Switch track's 36×20. Either add dedicated tokens or document them as intentional component-intrinsic constants (done here).

        
Clean
Fill/border bindings are consistent. Primary and Destructive share one fill+border recipe; Secondary and Disabled share a fill; nothing hand-hexed. Radius (radius/xs) and icon sizes (size/icon-md/-sm) are both real tokens.

        
Open
No Focus state on this component (same gap already open on Button and Input). Wire :focus-visible to focus/ring in code until a Figma variant exists.
