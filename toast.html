Toast node 943:475 · non-blocking status notification

A dismissible, non-blocking notification that appears at the edge of the viewport to confirm an action, deliver an update, or announce a system event. Five variants — Default · Success · Info · Danger · Disabled — resolve container fill, border, status glyph, and optional action-button colour from a single State variant axis. The Toast never blocks input; use Action Modal (§17) when the user must decide before continuing.

Anatomy

Container is a 440-wide auto-layout row with space/16 padding, space/12 gap, and radius/md (8). Three children in order: Status indicator (20×20 icon instance from §04, glyph swaps per state — Info filled · Check · info · Exclamtion), a Body column (space/8 gap) holding a text stack (Title/Sub title + Body description with space/4 between them) and an Actions row, and a Dismiss control (Icon Button §10 · Small, 30×30, Cancel glyph inside). Action button in Default/Success/Info uses the Secondary Button recipe; in Danger it flips to Destructive (filled red) so the retry affordance carries the tone of the message. The action button now carries a leading icon only — the trailing icon Figma shipped in the first pass was removed upstream (see changelog).

Updated 2026-09-11 (re-sync). Figma's Action button dropped its trailing icon across all four states — it now renders leftSection only. The playground, anatomy and contract below have been corrected to match; no other part of the Toast component changed in this pass.

Usage rules

Pick the state by the meaning of the message, not the desired colour. Success confirms a completed action; Info previews a scheduled or ambient event; Danger reports a failure that needs attention; Default carries a neutral update the user can act on when ready.

One action button per toast — never more. If the user needs to choose between two paths, that decision belongs in Action Modal (§17). The action label always leads with a verb and is bounded — Install now, Retry publish, View update, Learn more.

The status glyph is an instance of the Icons library (§04): Info filled · Check · info · Exclamtion. Never draw a glyph inline; never substitute a same-shape icon from another set.

Dismiss uses the Small Icon Button (§10) with the Cancel glyph. Do not build it as a raw 30×30 frame or replace the glyph with an "X" character.

Toasts stack vertically with space/12 between them, aligned to a viewport edge (bottom-right on desktop, top on mobile). Show at most three at once; older ones auto-dismiss first. Danger toasts stay until dismissed.

Auto-dismiss timing: Success 4s, Info 6s, Default 6s, Danger persist. Hovering a toast pauses its timer; the dismiss control remains available regardless.

Do
  • Use State=Success after a save/publish completes
  • Use State=Danger with a filled Destructive retry when a step failed
  • Bind fills to status/{tone}/bg and borders to status/{tone}/border
  • Put the action verb up front — Retry publish, not Publish retry
  • Instance the status glyph and Dismiss icon-button from their library components
Don't
  • Ship a toast with two or more action buttons — use Action Modal (§17)
  • Use Danger to celebrate ("Deleted!") — Success is for expected outcomes
  • Hardcode #FCEBE9 or the fg red — bind status/danger/*
  • Replace the Cancel glyph with a text "×" or a filled circle-close
  • Block interaction behind a toast; if you need blocking, it is a modal
