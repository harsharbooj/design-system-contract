11 Components · Checkbox

Checkbox Checkbox · 6 variants · node 842:365

A form-choice control for options that submit later — the counterpart to Switch's "takes effect immediately" toggle (see §09). A single variant axis, State, resolves to 6 published variants: Unchecked, Checked, Indeterminate, Disabled Uncheck, Disabled Checked, Disabled Indetermined. All six share the same 16×16, radius/xs box; only the fill and the interior mark change. Disabled variants use a flat gray fill (--text-3) instead of accent, with the check/dash rendered in a slightly darker gray (--text-2).

Indeterminate is a programmatic display state, not a third click target. A user can only toggle a checkbox between checked and unchecked; indeterminate is set in code (e.g. Mantine's indeterminate prop, which mirrors the DOM's el.indeterminate) to represent "some but not all" children checked in a group — clicking an indeterminate checkbox should resolve it to a definite Checked, never back to indeterminate.

Accessibility

      

        
Render a native <input type="checkbox">. Set Indeterminate via the element's .indeterminate DOM property (or Mantine's indeterminate prop) — there is no indeterminate HTML attribute, and aria-checked="mixed" is applied automatically by the browser once the property is set.

        
Pair every checkbox with a visible, clickable <label for=""> — never a bare box with no associated text, and never rely on a wrapping <div> with a click handler instead of the native input/label relationship.

        
Focus binds to focus/ring at 2px. Gap: no Focus variant in Figma — wire via :focus-visible in code until it lands.

        
A disabled checkbox — see Findings, no Figma variant exists yet — must still use :disabled / aria-disabled="true" in code and visually desaturate, matching the grayscale treatment Switch already applies to its own Disabled states.

      


      
Usage rules

      

        
Use Checkbox for choices that submit later (a form field, a filter selection, "select all" in a table). Use Switch (§09) for settings that take effect immediately. This is the same boundary Switch's own usage rules already draw — never substitute one for the other.

        
Reserve Indeterminate for a "select all" checkbox whose children are partially selected. Never let a user click their way into indeterminate directly — it is only ever set programmatically from the state of a related group.

        
Compose from the Checkbox component; never rebuild the box from a styled div, and never hardcode accent/solid's hex for the checked fill.

        
Only one size ships — 16×16. Don't scale a checkbox up for "emphasis"; use its paired label's type style to carry visual weight instead.

Findings from this pass
no Figma edits made — surface for review before a consistency pass

      

        
Found
No Disabled variant. Switch ships all 4 combinations of checked × disabled; Checkbox ships none. A data table's "select all" header checkbox and its row checkboxes will need a disabled treatment sooner or later (e.g. a row that can't be bulk-actioned) — recommend adding Disabled unchecked / Disabled checked variants the same way Switch already models them.

        
Found
No Focus/Hover state. Same open gap already flagged on Switch, Button and Input — wire :focus-visible to focus/ring in code until a variant is added.

        
Clean
Fully tokened for the states it does define. Box size reuses size/icon-sm (16), radius is radius/xs, fill is accent/solid, border is border/strong — nothing hand-hexed. The 14px check glyph and 8×2 dash are the only untokened constants, and both are intrinsic to the mark rather than layout values.

        
Clean
Indeterminate correctly replaces, not layers on, the check mark. The two interior marks are mutually exclusive in the component (see anatomy) — there's no risk of both rendering at once in code if the state mapping above is followed.
