02 Color System

Color system

Two layers. Primitives are the raw ramps (single value, no theme). Semantic tokens are role-based and mode-aware — they alias primitives and flip between Light and Dark. Screens must consume semantic tokens only; primitives exist to feed them. Dark mode lives entirely in the semantic layer.

Usage rules

Screens bind to semantic tokens only — bg/*, text/*, border/*, icon/*, action/*, status/*. A primitive (neutral/0, brand/600) on a screen fill is a defect to flag.

Surfaces stack bg/canvas (page) → bg/surface (cards) → bg/sunken (wells, segmented tracks). Don't paint a card with the canvas color or vice-versa.

Use the status families for meaning (success / danger / warning / info), each with fg · bg · solid · border. Don't hand-pick a green when status/success/* exists.

The label palette is for categorical tags only. It carries its own per-mode hex and must not be used for UI chrome or state.

Never read a hex off a swatch. Bind the token; let mode-switching resolve Light vs Dark. Typos text/sucess and border/Inverse should be aliased on the way into code.

Do
  • Fill cards with bg/surface, stroke with border/default
  • Use action/primary/bg + action/primary/fg on the primary button
  • Reach for status/warning/{bg,border,fg} for the recommendation banner
  • Let text/* resolve per theme automatically
Don't
  • Bind a screen fill to neutral/0 or brand/600
  • Hardcode #C22E22 where status/danger/solid exists
  • Use a label/* hue for a button or border
  • Maintain a second dark value by hand — the alias does it
