Left Side Navigation Design System Contract v0.9 · 67:431 · 1 slot · 148 instances

The app-level navigation rail, with one fixed structure and one slot. It is a single COMPONENT with no variant axes. Its only property is Nav Slot, which holds NavItem (Figma: Tab atom) instances. The brand block and the Settings / Exit footer are built into the component.

Slots
the most important part of this component's API

      

        
What a slot is here. A Figma SLOT property marks a region where a designer can drop in, remove and reorder children while the structure around it stays locked. In code a SLOT maps to children. If the team later adds more regions, each one becomes a named ReactNode prop. By contrast, an INSTANCE_SWAP maps to a single ReactNode prop, and a BOOLEAN maps to a conditional render.

        
This component's one slot. The layer is Nav Slot (node 859:17392), with property key Nav Slot#859:0. It's vertical, hugs its content, has px space/12 and gap space/12, and clips content. By default it holds 3 NavItems. preferredValues is the Tab atom set, added during the Figma cleanup and verified.

        
What belongs in it: NavItem only. Section labels or dividers could come later, but only if design approves them. What doesn't: buttons, inputs, cards, the brand block, or footer actions.

      

      

        
Do
    
          
  • Fill the slot with NavItems only
    • 
          
  • Keep exactly one item in the active (Figma Pressed) state
    • 
          
  • Order items the way the information architecture is ordered
    • 
        

        
Don't
    
          
  • Nest a second slot or sub-menu. No nested navigation is defined
    • 
          
  • Override NavItem width. It's 174 inside the 200 rail (12 + 174 + 12, with a 2px clip margin)
    • 
          
  • Put destructive actions in the slot. They belong in the footer (Exit)
    •

Layout behaviour

      

        
Fixed width of 200, full height. In code, use height: 100vh (or fill the shell) rather than Figma's 1024.

        
SPACE_BETWEEN pins the top group (brand + slot) to the top and the footer to the bottom, whatever the container height.

        
Fixed: the brand block, the footer rows and the widths. Flexible: the slot's contents only.

        
Min / max height: not defined in Figma. Overflow: not defined. The top group clips. Proposed The slot scrolls while the brand and footer stay fixed.

        
Responsive: not defined in Figma, and there are no breakpoint variables. Proposed only Below the tablet breakpoint, collapse to an icon rail or a drawer. This needs a design, including a Tooltip for collapsed labels.

Use cases

      

        
Primary app navigation
Scenario: the Paveway OCR web app, with 3–7 top-level destinations (Training Data, Manual Test, Auto Test). Why: it's persistent and one item is always active. Config: slot of NavItems, one active. Anti-pattern: two active items at once.

        
Workspace with utility actions
Scenario: Settings and Exit must always be reachable. Why: the footer is pinned by SPACE_BETWEEN, so it never scrolls away. Config: footer={['settings','exit']}. Anti-pattern: putting Settings in the slot.

        
Branded shell
Scenario: the product name and logo come from the tenant or product config. Config: productName and logo (proposed props). Anti-pattern: detaching the component to change the name.

        
Section switching without reload
Scenario: SPA routing. Config: active is derived from the current route and sets aria-current="page". Anti-pattern: local click state that goes out of sync with the URL.

        
Not for
In-page tabs (use Tab Status). Breadcrumbs, contextual or overflow menus, and mobile bottom nav have no library component, so flag them rather than inventing one. Also not for more than ~8 destinations or nested trees.

      


      
Accessibility

      

        
The container is <nav aria-label="Main navigation">. The brand block is not a landmark.

        
NavItems are real links (<a href>). The current one has aria-current="page". The active item isn't shown by colour alone: it also has a fill and a 1px border, which is a good property of the design.

        
Icons are decorative, so they get aria-hidden="true". The label is always present, because the Icon boolean hides only the icon.

        
Focus: a visible :focus-visible ring is required but isn't in Figma. The preview borrows Button's focus/ring.

        
Exit is styled as destructive but isn't a destructive action. Ask for confirmation only if leaving discards unsaved work.

Usage rules

      

        
Do
    
          
  • Instantiate the component and fill Nav Slot with Tab atom instances
    • 
          
  • Drive the active item from the route (aria-current="page")
    • 
          
  • Keep Settings / Exit in the footer, where they're pinned
    • 
          
  • Use the --mantine-* tokens for every colour and spacing value
    • 
        

        
Don't
    
          
  • Detach the component to change the product name or logo
    • 
          
  • Widen the rail to 240 because size/sidebar says so, until that's decided
    • 
          
  • Invent a collapsed or icon-only mode or a tooltip. None is designed
    • 
          
  • Hardcode #E4E2DD for the edge instead of border/subtle
    • 
        

      


      
Open questions & contract gaps

      

        
High
1 · Focus and Disabled are not designed on Tab atom. Hover and Pressed now exist.

        
Med
1b · Pressed is really the selected / active look. It was renamed from Selected and still marks the current page (150 instances). Recommendation: add a separate Selected variant. Also: Hover has 0 instances, and the duplicate NavItem set (271:6610, 0 instances) should be deleted or merged.

        
Med
3 · The footer isn't a slot and doesn't use NavItem. Settings and Exit are hand-built frames in Body (400), while NavItem uses Body/Strong (500). They have no hover or focus states, and both row layers are named "Settings". The icon x-positions do line up (12 slot padding + 12 item padding = 24 footer padding).

        
Med
4 · The logo mark and product name are not properties. You can't change them per product without overriding them. The logo is a local frame, not a component.

        
Med
5 · Width mismatch. The component is 200 wide, but the size/sidebar token (Dimensions) is 240. Either bind the width or retire the token.

        
Med
6 · Not defined: collapsed or icon-only mode, responsive behaviour, scroll overflow, and long-label truncation. The playground shows proposals only.

        
Low
7 · Prototype reactions (ON_CLICK → CHANGE_TO) are for prototyping only. There's no real selection contract.

        
Low
8 · Code Connect: get_code_connect_map and get_context_for_code_connect return "needs a Dev or Full seat on an Organization or Enterprise plan" for 67:431 and 852:10111. No Code Connect mapping exists yet, so the Mantine mapping on this page is proposed.

        
High
10 · Dark-mode contrast. text/destructive (Exit) on bg/surface is 4.14:1, and the logo glyph text/inverse on action/primary/bg is 3.07:1. Both fail AA.
