The design system as a contract

A machine-readable reference for the design system, extracted directly from Figma. It exists so a design-time agent (Claude in Figma) and a dev-time agent (Claude + Mantine) consume the same vocabulary — tokens, not pixels. Read the tables for coverage; read the contract blocks at the end of each section for the values an agent must respect.

How to read this contract

Each section carries four things: a token reference table (name · value · recommended Mantine prop · usage), a short set of numbered usage rules, a do / don't pair, and a machine-readable contract block (<script type="application/json">) that a future Claude session parses to know what to reuse and what is forbidden. Coverage is what the agent may reuse; the forbidden array is what it must never do.

Usage rules

Always use Body (14/22) for form-field values and table cells, and Label (13/18) for the labels above them. Never set a raw font-size.

Numbers that read as data — KPIs, counts, IDs, timestamps in tables — use a Mono style so digits align. Mono/Metric-L is reserved for hero KPI figures; don't use it for body counts.

Overline is the only uppercase style. Use it for metric-card eyebrows and table column headers; never uppercase a Title or Body style manually to fake it.

One title style per level: Title/Page → Title/Section → Title/Sub. Don't skip a level or restyle a Body to stand in for a heading.

Only Geist and Geist Mono ship in the system. Any other family is off-contract and must be flagged, not substituted.

Do
  • Apply the shared Body style to every field label and value
  • Use Mono/Metric-L for the four KPI numbers on the build screen
  • Let Overline carry table headers and card eyebrows
  • Bind text fills to text/* tokens, not primitives
Don't
  • Type fontSize: 14 when Body already means 14/22
  • Reach for Mono/Metric-L for ordinary counts
  • Uppercase a Title style to imitate an overline
  • Introduce a third typeface for "emphasis"

Usage rules

Screens bind to semantic tokens only — bg/*, text/*, border/*, icon/*, action/*, status/*. A primitive (neutral/0, brand/600) on a screen fill is a defect to flag.

Surfaces stack bg/canvas (page) → bg/surface (cards) → bg/sunken (wells, segmented tracks). Don't paint a card with the canvas color or vice-versa.

Use the status families for meaning (success / danger / warning / info), each with fg · bg · solid · border. Don't hand-pick a green when status/success/* exists.

The label palette is for categorical tags only. It carries its own per-mode hex and must not be used for UI chrome or state.

Never read a hex off a swatch. Bind the token; let mode-switching resolve Light vs Dark. Typos text/sucess and border/Inverse should be aliased on the way into code.

Do
  • Fill cards with bg/surface, stroke with border/default
  • Use action/primary/bg + action/primary/fg on the primary button
  • Reach for status/warning/{bg,border,fg} for the recommendation banner
  • Let text/* resolve per theme automatically
Don't
  • Bind a screen fill to neutral/0 or brand/600
  • Hardcode #C22E22 where status/danger/solid exists
  • Use a label/* hue for a button or border
  • Maintain a second dark value by hand — the alias does it

03 Spacing & Grid

Spacing & grid

A 4px base with an 8-anchored scale (one 2px half-step). Radius, stroke and named sizes round out 34 dimension tokens. Layout is a fixed 240px sidebar, a 56px top bar and a 1200px max content column; content padding is 32px with a 40px bottom. Spacing is a binding contract: every component gap and padding must bind to a space/* variable, never a typed pixel — see the binding rule below.

Usage rules

Binding rule (hard requirement). Every Auto Layout gap and padding MUST be bound to a space/* variable. A raw pixel value where a token exists is a defect that must be flagged and the output stopped — it is not an acceptable "matched-number" fallback (a bound space/16 and a typed 16px are not equivalent).

No interpolation. Values that fall between steps (6, 10, 14, 18) are not tokens. Either round to the nearest existing step and bind, or promote the value to a real token first. Never interpolate a between-steps number.

Layout exception. Page-level / editorial layout spacing — outer page margins and chapter-gap spacing in a documentation layout — MAY be off-scale; this is a sanctioned exception. Component- and content-level spacing (card padding, row/stack gaps, list items) MUST bind — no exceptions, and the page-margin exception must never be used inside a component.

Card padding is space/16; comfortable cards use space/20. The KPI cards' 18px vertical padding is off-scale — round to space/16 or space/20 and bind.

Radius is role-based (radius/sm controls, radius/md cards, radius/full pills), and layout dims — sidebar 240, top bar 56, content max 1200, page padding 32/40 — come from size/* tokens, never literals.

Avoid the one-off space/52 in new work; prefer space/48 or space/64 so the scale stays legible to the agent.

Do
  • Set gaps with gap="md" (16) between card groups
  • Round the KPI card to space/20 vertical padding
  • Use radius/md on cards, radius/sm on buttons
  • Pull layout dims from size/sidebar, size/topbar
Don't
  • Write padding: 18px — no such token exists
  • Introduce new values between scale steps
  • Give every surface the same radius and shadow
  • Hardcode 240 or 1200 in a layout

Anatomy

      
Container is a 440-wide auto-layout row with space/16 padding, space/12 gap, and radius/md (8). Three children in order: Status indicator (20×20 icon instance from §04, glyph swaps per state — Info filled · Check · info · Exclamtion), a Body column (space/8 gap) holding a text stack (Title/Sub title + Body description with space/4 between them) and an Actions row, and a Dismiss control (Icon Button §10 · Small, 30×30, Cancel glyph inside). Action button in Default/Success/Info uses the Secondary Button recipe; in Danger it flips to Destructive (filled red) so the retry affordance carries the tone of the message. The action button now carries a leading icon only — the trailing icon Figma shipped in the first pass was removed upstream (see changelog).

Usage rules

      

        
Pick the state by the meaning of the message, not the desired colour. Success confirms a completed action; Info previews a scheduled or ambient event; Danger reports a failure that needs attention; Default carries a neutral update the user can act on when ready.

        
One action button per toast — never more. If the user needs to choose between two paths, that decision belongs in Action Modal (§17). The action label always leads with a verb and is bounded — Install now, Retry publish, View update, Learn more.

        
The status glyph is an instance of the Icons library (§04): Info filled · Check · info · Exclamtion. Never draw a glyph inline; never substitute a same-shape icon from another set.

        
Dismiss uses the Small Icon Button (§10) with the Cancel glyph. Do not build it as a raw 30×30 frame or replace the glyph with an "X" character.

        
Toasts stack vertically with space/12 between them, aligned to a viewport edge (bottom-right on desktop, top on mobile). Show at most three at once; older ones auto-dismiss first. Danger toasts stay until dismissed.

        
Auto-dismiss timing: Success 4s, Info 6s, Default 6s, Danger persist. Hovering a toast pauses its timer; the dismiss control remains available regardless.
