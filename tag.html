One variant axis, Status, resolves to 6 published variants, plus three component properties (label text, dot visibility, icon visibility). Unlike Button and Input, every fill/foreground pair here already binds correctly to its status token — the one thing this pass found is a size mismatch on the close icon (below).

Close icon — the Cancel glyph from the Icons library (§04 · now added to the catalog there), toggled with showIcon. 14×14 on five statuses, 16×16 on Accent — see the flag below; 16 (size/icon-sm) is the only one of the two that is actually a token. Close-icon size is inconsistent across variants. Success / Danger / Warning / Info / Neutral render the close icon at 14×14 — an off-scale size, since size/icon-* only defines 16 / 20 / 24. Accent alone renders it at 16×16 (size/icon-sm), which is the correct token. Pick one: rebind the other five to 16×16, or add a documented size/icon-xs (14) token if 14 is intentionally the dense-tag size — right now the five and the one disagree with no token backing either.

Neutral and Accent are the two statuses that don't draw from a status/* family — Neutral borrows the generic surface pair (bg/sunken + text/secondary), Accent borrows the brand pair (accent/bg + accent/fg). Both are legitimate semantic tokens, so this isn't a binding defect — just worth knowing there are really two token families feeding one component.


      
Accessibility

      

        
The tag itself is not interactive — render it as a <span> (or Badge's default element), not a button, unless the whole tag is clickable.

        
The close icon is interactive when showIcon is true — render it as a real <button aria-label="Remove {label}">, never a bare <img> or <svg> with a click handler.

        
Gap: no focus-visible style is defined for the close icon in Figma. Wire :focus-visible to focus/ring in code until a state is added.

        
The status dot is decorative — mark it aria-hidden="true"; the status must also be conveyed by the label text, never by color/dot alone.

      


      
Usage rules

      

        
Map status to Mantine exactly: Success=green, Danger=red, Warning=yellow, Info=blue, Neutral=gray, Accent=brand — always with variant="light". Never hand-pick a pastel color to fake a status.

        
Use Neutral for states with no positive/negative meaning (e.g. "Draft", "Unlabeled") and Accent for categorical / brand-owned tags — not as a stand-in for Info.

        
Show the close icon only on tags the user can remove (e.g. an active filter chip). A read-only status tag on a table row should set showIcon=false.

        
Keep the dot on by default — it's what makes status scannable in a dense list at a glance. Turn it off only in already-color-coded contexts (e.g. inside a colored banner).

        
Compose from the Tags component and its props; never rebuild a tag from a styled div or hardcode a status hex.
